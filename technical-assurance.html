Technical assurance

Technical assurance and BMS integration

EcoAI is designed to work with the BMS infrastructure already in place. The existing BMS remains the control system, while EcoAI supports continuous optimisation within agreed comfort, operational and technical limits.

Assurance principles

  • BMS remains in control Local logic, alarms, safeties and schedules stay in place.
  • Selected points only Optimisation points are agreed during technical validation.
  • Defined limits Comfort, operating and site-specific constraints are set before optimisation begins.

Existing control system

The existing BMS remains in control

EcoAI does not replace the BMS. Local plant control, safety logic, alarms, schedules and existing operational protections remain in place. EcoAI works through selected optimisation points agreed during technical validation, helping improve performance without requiring a rip-and-replace project.

Building data

What EcoAI reads

EcoAI can use relevant BMS and building data where it is available, appropriate and useful for optimisation. The exact points are reviewed during technical validation.

  • Temperatures
  • Setpoints
  • Valve and damper positions
  • Fan and pump operation
  • Occupancy or schedule signals where available
  • Energy data where available
  • Weather and forecast data

Performance context

What EcoAI adds to the existing BMS

A BMS is effective at running local control logic, schedules and plant operation. EcoAI adds a predictive optimisation layer that brings wider context into those decisions.

By using weather forecasts, occupancy or schedule patterns where available, thermal mass and historic building behaviour, EcoAI helps the building move from reactive control to proactive performance improvement.

This helps the existing BMS operate with better timing, supporting more stable internal conditions while reducing unnecessary runtime, energy use and carbon emissions.

Selected optimisation

How EcoAI applies optimisation

Where appropriate, EcoAI applies optimisation through selected HVAC control points, such as setpoints, offsets or other agreed parameters. These changes are made every 15 minutes within defined comfort and operational limits, helping the existing BMS run the building more efficiently without bypassing local control logic.

Operating boundaries

Comfort and operational limits

Comfort limits, operating hours, rate-of-change limits and any site-specific constraints are agreed before optimisation begins. This ensures that energy and carbon savings are pursued without compromising the building's operational requirements.

Practical deployment

Targeted optimisation where appropriate

EcoAI does not need to optimise every system or every part of a building from day one. Where site constraints exist, optimisation can be targeted to selected HVAC systems, zones or control points that are technically suitable and commercially worthwhile.

This allows projects to start in the areas where the strongest opportunity exists, while leaving other systems under normal BMS operation where optimisation is not appropriate.

Fallback behaviour

What happens if optimisation pauses

If optimisation is paused or communication is interrupted, the existing BMS continues to operate using its normal control logic. This fallback principle is central to EcoAI's approach: the building is not dependent on continuous external control to remain operational.

The EcoAI portal also helps make the impact visible. Where optimisation is paused for review or comparison, estates teams can see how building performance changes when continuous optimisation is active versus inactive.

Controls collaboration

Role of the BMS contractor

The BMS contractor may support access, point identification, permissions and technical validation. EcoAI's role is to work with the existing controls environment, not bypass it. This makes the process collaborative and practical for estates and FM teams.

Before implementation

Technical validation before implementation

  • Confirm BMS compatibility
  • Identify suitable optimisation points
  • Review data availability and quality
  • Agree comfort and operational limits
  • Confirm remote access route
  • Confirm fallback behaviour
  • Agree implementation responsibilities
